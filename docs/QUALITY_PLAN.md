# Clide3D Quality Plan: from clay to feature-film characters

**Status (2026-10-27):** Stages 1a, 1b, 1c, 2, 3a, 3b, 3c, 3d, 4a, 4b, 4c, 4d, 5a, 5b and the optional 5c are done (see their result paragraphs); the final gate is plan only. Written on branch `sculpt` after Stages 0-8 of docs/SCULPT_PLAN.md shipped (72 MCP tools). Every stage below names the files and functions it changes; line numbers were read on this branch and drift as code moves.

The goal is model quality at the level of a feature-animation studio's stylised characters: smooth, intentional surfaces with crisp creases, clean quad topology with subdivision and displacement, groomed hair, and appealing proportions. The plan does not decide what "looks like a feature film"; the user does. It decides what can be measured, so each stage has a numeric exit criterion, and it ends with a benchmark character whose numeric checks must pass before the user's final sign-off.

The plan starts from defects found while a detailed figurine was sculpted entirely through MCP. They are Stage 1, the first and cheapest stage, because every later stage builds on surfaces and exports that are currently unreliable.

File references of the form `app/eyes.rs:N` mean `src/app/eyes.rs`. "The sculpt plan" means docs/SCULPT_PLAN.md.

## 0. Decisions (2026-10-25)

The user wants autonomy. Every open choice therefore has a recommended default, marked **(default, user may override)**. An implementer follows the default unless the user has said otherwise; each stage notes the defaults it uses. The only items that block on the user are new dependencies (§0.1).

**Representation**
- **D1. Clay stays the source of truth for sculpting** (default, user may override). Polygon objects (Stage 3) are derived from clay by retopology and carry their own subdivision levels and displacement. Clay edits after a retopo do not flow into the polygon object automatically; `poly project` re-runs the projection on demand. This keeps the sculpt plan's §2 architecture.
- **D2. The polygon object is a new `Shape::Poly`** with an `Object::poly` field (default, user may override). It absorbs the sculpt plan's deferred Stage 9a specification (chunked Arc storage, CSR topology). The triangle `Shape::Mesh` import stays as it is.
- **D3. Polygon records are not in the stroke ledger** (default, user may override). Retopo, subdivision and projection are deterministic functions of (clay, arguments). The object stores those arguments (`Poly.made_by`) so `poly rebuild` reproduces it. Scene undo covers edits. Brush strokes on a polygon object (Stage 4b texture paint) do use the ledger, because they are spatial records like clay paint.

**Stage 1 fixes**
- **D4. Round tubes get an exact distance field** (default, user may override). A sweep whose profile is `{circle: r}` (new) is evaluated as the union of exact round cones along the densified path. Polygon profiles keep a sweep, rebuilt on rigid per-segment frames with mitre caps (Stage 1b).
- **D5. Old saved sweeps mesh exactly as before** (default, user may override). A new field `Form::Sweep.field` defaults to `legacy` when it is absent from saved JSON. The `edit_clay` handler fills `field: "segments"` on every sweep blob that the call adds or replaces without one. This follows the sculpt plan's rule that resolved defaults are stored, not re-derived (its §3.3). Old scenes keep their pinned mesh hashes; new sweeps get the fix.
- **D6. Round-profile sweeps are smooth forms** (default, user may override). They leave the hard-surface resolution floor (`Clay::mesh_resolution`, clay.rs:2107) and the sharp-feature path (`Clay::sharp_features`, clay.rs:2077), as capsules and chains already do.
- **D7. Print export separates pinched sheets by a small offset** (default, user may override). It does not weld them back. The offset is max(0.005 mm, 0.02 × the local cell), applied after the weld in `export_print` only, so viewport, bake and film meshes stay bit-identical.
- **D8. ClayPolish is a ledger record**, not a mesh filter (default, user may override). It is `edit_clay polish` and `sculpt brush: clay_polish`, both through one engine kernel. The existing `Brush::Polish` (the planar press) keeps its name and behaviour.
- **D9. Projected stroke points are resolved at commit** (default, user may override). The record stores the projected points, so replay never casts rays again. This matches the sculpt plan's screen frames.
- **D10. Raised limits** (default, user may override):
  - `surface_point`: 1,024 rays and 1,024 points per call, refused above that (never truncated);
  - blob paths (sweep, chain, band, array points): 512 points;
  - stroke points stay 512 (`resolve::MAX_POINTS`).
- **D11. Heavy rebuilds return early** (default, user may override). An `edit_clay` whose mesh build passes `wait_s` (default 20 s) replies with `mesh_pending: true`. The build keeps running with progress in `job_status`. Today the call blocks until the build ends.

**Agent feedback**
- **D12. Metrics are computed on the clay field, not on images** (default, user may override). Field metrics do not depend on the camera or the tessellation. Images are for agents and humans to look at, and for silhouettes.
- **D13. Reference images per view** (default, user may override). `set_reference` keeps one reference per view slot (front, back, left, right, top, three_quarter). Single-reference calls keep working and fill the `front` slot (or the `view` given).
- **D14. Default quality thresholds** (default, user may override). They are calibrated in Stage 2 against synthetic fixtures, then fixed in `quality_report`:
  - lumpiness ≤ 0.05 (RMS band-pass residual in cells, outside intended detail);
  - silhouette IoU ≥ 0.95 per view;
  - contour error ≤ 1% of the subject height;
  - close-up feature chamfer ≤ 1.5% of the crop radius;
  - export watertight.

**Topology**
- **D15. Retopology is in-house, Instant-Meshes style** (default, user may override): a 4-RoSy orientation field plus a position field, solved by deterministic multicolour Gauss-Seidel on a hierarchy. QuadWild's integer-programming step is not used, because it needs a MIP solver. If the user later allows an external engine behind a feature flag, it plugs into the same `retopo` tool.
- **D16. Catmull-Clark with semi-sharp creases** (DeRose et al. 1998) and boundary rule "edges and corners" (default, user may override). This is generalised from `human::subdivide` (human.rs:391).
- **D17. Detail is stored per level as tangent-space vector displacement** (default, user may override). Exported maps are vector displacement in tangent space as 32-bit EXR, plus a scalar 16-bit PNG height map for tools that want one.
- **D18. Export: OBJ cage (quads) plus maps, and GLB at a chosen level, are the minimum** (default, user may override). An ASCII `.usda` writer is optional and in-house. It needs no dependency, because USDA is text.

**Look dev**
- **D19. UDIM tiles are 1001-1100, at most 100 tiles of up to 8192², 16-bit** (default, user may override). Paint is stored in sparse 256² pages per tile.
- **D20. Groom edits change `Hair.guides` in place**, with no ledger (default, user may override). Whole-scene undo and `history` cover them. Each `groom` call is deterministic.
- **D21. Stylised shading ships as material and eye presets**, not as a new renderer path (default, user may override): `skin_stylized`, `lips_stylized` and eye `style: stylized`.

**Appeal**
- **D22. A turnaround sheet is split into per-view references by subject bounding boxes** in reading order (default, user may override), with a shared scale. A sheet whose views cannot be found automatically takes explicit `boxes`.
- **D23. The stylised base is a parametric blob generator** (`create_character`), not a mesh asset (default, user may override). Its only input is proportions, so no existing character's design is involved.
- **D24. The benchmark character is an original friendly cartoon creature** (default, user may override), specified in §5. The user may substitute another original design; the checks do not change.

**Process**
- **D25. One commit per sub-stage, each with a dated result paragraph** (default, user may override). The paragraph records results, deviations and measured figures, as in the sculpt plan.

### 0.1 New dependencies (need explicit user approval)

Policy: prefer in-house pure Rust. Already approved and present: `xxhash-rust`, `zip`, `exr`, `objc2-app-kit`, and an external `ffmpeg` binary. Already present before that: `meshopt`, `xatlas-rs-v2`, `flate2`, `png`, `image`.

**Recommended default: no new crates.** Each candidate below has an in-house fallback that the plan uses unless the user approves the crate.

| Crate | Licence | What for | Stage that would block | In-house fallback (the default) |
|---|---|---|---|---|
| `faer` | MIT | Sparse Cholesky / LU for least-squares solves: retopo field smoothing with hard constraints, UV relaxation, displacement reconstruction | 3b, 3c (only if the fallback misses its time bound) | Jacobi-preconditioned conjugate gradient on CSR matrices (about 150 lines), plus the multicolour Gauss-Seidel the field solver uses anyway |
| `nalgebra` | Apache-2.0 | Small dense eigen-solves (3×3 symmetric curvature tensors, 2×2 shape operators) | none | `glam` plus a closed-form 3×3 symmetric eigen-solver (Smith 1961; about 40 lines) |

No crate exists for Instant Meshes, QuadWild, OpenSubdiv or USD in pure Rust that the plan would want. Those are in-house (D15, D16, D18).

### 0.2 Rules every stage keeps (lessons from the sculpt plan)

1. **Settle before changing replay inputs.** Any handler that changes blobs, regions, cells or a clay's composed field calls `settle_clays` (app/tools.rs:701) first, so unchecked ledgers replay against the blobs they were made on. That covers `edit_clay` field changes, `edit_clay polish`, `retopo`, `poly project` and `export_poly`. Read-only tools that read the composed field (`quality_report`, `compare_reference`) settle too, because `export_print` already does.
2. **Bound agent-supplied sizes before allocating.** Each schema below states its maximums. Handlers refuse oversize requests from the arguments alone, before any grid, image or mesh is allocated, with a message that says what fits. That covers lattice sizes, triangle estimates, tile counts, ray counts and point counts.
3. **Result-changing fields go into `Record::digest`** (ledger.rs:434). New record kinds (ClayPolish, projected strokes, polygon texture paint) hash every field that changes what they write. `RecordOp::Action` is already JSON-hashed, so action fields are covered once they are in its payload.
4. **Bit-identical across thread counts.** New kernels are Jacobi (each output a pure function of the previous pass) or multicolour Gauss-Seidel with a fixed colour order. There are no parallel float reductions inside one output. Every new kernel has a 1-thread against 12-thread hash test, using `clay::with_threads`.
5. **AI-first.** Every feature is an MCP tool, or a new argument on one, first. The UI sends the same request through `send_ui_call`, and a test compares the request and reply of the UI path and the agent path.
6. **Engine versioning.** A change to what an existing brush writes bumps `ENGINE_VERSION` (sculpt/engine.rs). New brushes do not. A change to the blob field (D4) is not an engine change, but it changes context hashes; D5 keeps old files unchanged.

## 2. What the figurine session found, traced to code

A detailed figurine sculpted through MCP hit seven problems. Reading the code points to these causes. Each Stage 1 sub-stage starts with a regression test that reproduces the defect on synthetic geometry, so the cause is confirmed before the fix lands.

| # | Symptom | Cause in the code (to confirm in the stage's first test) |
|---|---|---|
| 1 | Thin sweep tubes (r ≈ 0.004-0.02) on curved paths mesh fuzzy and lumpy; `sharp: false` did not help | **Field.** `Geometry::sdf_within` for `Sweep` with `path_smooth` (hard_surface.rs:1389) finds the nearest chord of the densified spline (`spline_path`, hard_surface.rs:561, already 8-96 points per span), then runs 8 Newton steps on a uniform Catmull-Rom through those densified points. That curve is not the one `spline_path` built, which used distance-weighted tangents. Each step may move only one segment, and `t` is clamped at span ends. The section is evaluated in a frame that is slerped and then re-aimed with `from_rotation_arc`, and `local.z` is dropped. Where the foot point jumps or fails to converge, nearby points get unrelated feet, so the field is not 1-Lipschitz and surface nets see noise. A circle authored as an N-gon profile also adds facets about 0.076r deep at N = 8, which spiral as the transported frame turns. **Meshing.** Any sweep makes the clay "hard" (`mesh_resolution`, clay.rs:2108), so the default resolution floors to 192-512, and `sharp_features` sends it through QEF feature placement on that noisy field. `sharp: false` only removes the second effect. |
| 2 | `export_print` with `detail_regions` and `fine: true`: 186 edges not used exactly twice, at region seams | `adaptive::make_manifold` (adaptive.rs:798) repairs pinches by giving each sheet a **copy of the vertex at the identical position** (`positions.push(positions[v])`). `export_print` (app/importing.rs:432) then welds by exact position (`mesh_asset::weld`, mesh_asset.rs:216), which merges every copy back, so `edge_use` (mesh_asset.rs:235) counts those edges as non-manifold. Secondary cause: `Nets::mesh` (adaptive.rs:510) drops a crossing whose ring collapses (`ring.len()` 2, or 4 with `ring[0] == ring[2]`), which can leave odd-count edges at 2:1 size changes. The uniform fine mesh never calls `make_manifold` (it falls back to marching tetrahedra), which is why a uniform `detail_cell` exported clean, at 16M triangles. |
| 3 | `compare_reference` ignored `center` / `radius` | The schema (mcp.rs:1141) has only `view` and `match`. `align` (app/eyes.rs:381) frames the whole model against the reference's subject box. Only `render_views` (app/eyes.rs:305) reads `center` and `radius`. |
| 4 | No curvature-aware smoothing; every lip and lid line needed hand smoothing | `Brush::Smooth` (sculpt/brushes.rs:287) is an isotropic 7-point Laplacian of the field: it rounds creases as fast as lumps. `Brush::Polish` is a planar press. `to_clay::smooth` (to_clay.rs:247) has a mean-curvature flow with volume kept, but only inside the DynaMesh remesh, on a dense grid. |
| 5 | Crease strokes along long strands drift where the surface passes from one blob to another | `frame: surface` and `snap` resolve each point with `Surface::snap` (surface.rs:30), the *nearest* surface point (brush/resolve.rs:345-395). Across a concave junction (two blobs meeting at an angle), nearest-point snapping jumps between the two sheets. The agent's workaround, casting rays in each strand's plane, is not available inside a stroke. |
| 6 | Clays with dozens of carve sweeps at a fine cell rebuild for minutes | `Field::prefix_full` (clay.rs:977) skips a blob by its box only when it is not a carve (`!matches!(prim.op, Op::Carve \| Op::Intersect)`, clay.rs:988). Every carve in a block's `near` list is therefore evaluated at every grid point. Each smooth-sweep evaluation scans every densified segment (up to 96 per span × 127 spans) and then runs 8 Newton steps, and it ignores the `bound` argument. The hard floor in row 1 multiplies the grid size on top. `edit_clay` waits for the build (`MeshLib::sync`, mesh.rs:400), with no progress and no budget. |
| 7 | `surface_point` at most 256 rays; array paths at most 128 points | `rays.len() > 256` is refused (app/probe.rs:44), but `points` are silently truncated by `.take(256)` (app/probe.rs:60). `chain_points` (clay.rs:417) and `hard_surface::validate` (hard_surface.rs:1769) cap paths at 128. |

## 4. Stages

Every acceptance test runs under `cargo test --release`. Image goldens are `#[ignore]` unless `CLIDE_GPU=1`, and perf assertions run with `CLIDE_PERF=1` (3× slack logged otherwise), as in the sculpt plan. Synthetic fixtures live next to the code they test (clide3d is a binary crate; `src/harness/` holds shared measures).

### Stage 1a: close-up compare, watertight local detail, limits (S-M, 1 week)

**Status: done (2026-10-25)**, on branch `sculpt`; 72 tools. See the result paragraph at the end of this stage.

**Goal.** Agents can compare close-ups against the reference, local fine detail exports watertight, and probe limits refuse rather than truncate.

**MCP changes**

`compare_reference` (schema at mcp.rs:1141):
```json
{
  "view": "front|back|left|right|top|bottom|three_quarter | {dir:[x,y,z]}",
  "match": "height|width",
  "center": [x, y, z],          // close-up: world point to crop around (needs radius)
  "radius": 0.001..1000,        // close-up half-size in world units
  "size": 64..1024              // panel long side for the close-up (default 512)
}
```
The reply adds `closeup: {center, radius, crop_px: [x0, y0, x1, y1], reference_px_per_unit, interior: bool}`. `pixel_to_world` is given for the crop panel.

`surface_point` (mcp.rs:696): `rays` and `points` are each at most 1,024 (D10), refused above that with the count. New `offset` and `limit` page through long `at` lists, and the reply gives `next_offset` when more remain. The description states the bound and the batching rule.

`export_print` (mcp.rs:1475):
```json
{
  "max_triangles": 1000..50000000,   // refuse (before building) when the estimate is larger, and (writing nothing) when the built mesh is; default 20M
  "simplify": { "error_mm": 0.001..1 } // meshopt simplification after weld, then re-checked
}
```
The reply adds `non_manifold_by_kind: {open, over_used, pinched}`, `pinches_separated`, `estimated_triangles` and `simplified_from`.

**Files and functions**
- `app/eyes.rs`: `align` keeps the whole-model fit (same `s`, `uc`, `vc`). New `Align::crop(center, radius)` returns the crop rectangle in panel pixels and the matching orthographic shot. `compare_reference` renders the model at crop resolution with `ortho = radius` (not the whole panel's height) and resamples the reference crop from the full-resolution `Reference.image` (bilinear), not from the 512-pixel panel. `region_report` runs on the crop.
- `app/probe.rs:44, 60`: shared limit `MAX_PROBES = 1024`, an explicit error instead of `take(256)`, and `offset` / `limit` handling.
- `clay.rs:417` `chain_points` and `hard_surface.rs:1769` `validate`: 512 points (D10). Membrane stays at 20.
- `app/importing.rs:432` `export_print`: estimate triangles before building (the adaptive estimate `Nets::mesh` already computes, exposed as `Clay::fine_estimate`), weld, then the new `adaptive::separate_pinches` (D7), then optional meshopt simplify, then `edge_use` again.
- `adaptive.rs`: new `pub(crate) fn separate_pinches(points: &mut Vec<Vec3>, tris: &mut Vec<[u32; 3]>, offset: f32) -> usize`. It runs `make_manifold` on the welded mesh, then moves each copy by `offset` toward the area-weighted centroid of its own triangle group, projected on that group's mean normal. `make_manifold` itself is unchanged, so viewport meshes keep their pinned hashes (`OLD_FINE`).
- `adaptive.rs:510` `Nets::mesh`: count collapsed rings (debug counter as for `TETRA_FALLBACKS`). If the 1a regression shows open edges from them, replace the drop with a fan to the leaf vertex of the coarser side. The coarser leaf's vertex is then shared by both finer quads, which is the octree dual-contouring rule the module comment already describes.
- `mesh_asset.rs:235` `edge_use`: a new `edge_use_kinds` returns used-once (open), used-3+ (over-used) and used-4/6 at a single position pair (pinched) separately.

**Algorithm: close-up crop.** Project `center` with the aligned camera: `x = (center·right − (uc − w/2s))·s`, `y = ((vc + h/2s) − center·up)·s`. The crop is the square `[x − radius·s, x + radius·s]` (likewise y), clamped to the panel. The model is re-rendered from the same direction with its target at `center` and orthographic half-height `radius`, at `size` pixels. The reference crop is cut at `1/k` scale from the source image, so close-ups use the reference's native resolution. `interior: true` when at least 98% of the crop's pixels lie inside both masks, which means silhouette IoU says little there and Stage 2's feature compare is the meaningful number.

**Tests**
- `closeup_compare_crops_both_panels` (app/eyes tests, headless editor through MCP): a sphere scene with a synthetic reference (a disc with a smaller dark disc as an "eye" off-centre). A close-up at the eye gives `crop_px` centred on the eye within 1 px, and the IoU of the eye-disc mask against a model with a matching bump is ≥ 0.9. Without `center` the reply is byte-identical to today's.
- **Defect 2 regression,** `region_seams_export_watertight` (app/importing tests): a unit sphere at `detail_cell` 0.02 with one region (cell 0.005, radius 0.3) and pore-noise strokes, including a stroke that makes a pinch (two pits 0.6 cell apart). `build_fine` then the full `export_print` path (`fine: true`, STL, read back with the STL reader) gives `non_manifold_edges == 0` and `inconsistent_edges == 0`. The test also checks that the bug is reproduced: before the fix, the same fixture reports `pinched > 0`.
- `separate_pinches_keeps_geometry`: Hausdorff of the separated mesh to the unseparated one is ≤ 1.01 × offset, and the volume change is ≤ 1e-4 relative.
- `fine_meshes_unchanged`: `OLD_REGULAR` and `OLD_FINE` (adaptive.rs:354-355) still match.
- **Defect 7 regression,** `probe_limits_refuse_not_truncate`: 300 `points` give 300 results (today 256); 1,025 are refused with a message naming 1,024; `offset` / `limit` paging returns the same results as one call.
- `export_print_refuses_before_building`: a `max_triangles` below the estimate is refused in under 50 ms, with the estimate in the message.

**Performance.** A close-up compare at 512 px takes ≤ 1.5× a full compare. `separate_pinches` on 4M triangles takes ≤ 1.5 s. The export estimate takes ≤ 50 ms.

**Risks.** Slicers weld with their own tolerance; an offset below it is merged again. D7's 0.005 mm floor sits above common slicer tolerances (about 1e-4 mm), and the reply states the offset used. meshopt simplification can create non-manifold edges; the result is re-checked and, if not watertight, the unsimplified mesh is written and the reply warns.

**Exit criterion.** The defect 2 fixture exports with 0 non-manifold edges at local detail, and a body-scale fixture (1 m tall, regions at 0.25 mm on face and hands, 1 mm elsewhere) exports watertight at ≤ 25% of the triangles of the uniform-cell export that was the only option before. Close-up compare passes its test, and probe limits refuse.

**Stage 1a result (2026-10-25).** All of the MCP changes above shipped as specified, with the deviations below. Tool count stays 72.
- **Defect 2 had three causes, not the two in §2.** Each has a fixture that fails on the old code (`adaptive::clay_tests`; the fixtures are a unit sphere at detail cell 0.02 with a 5 mm region and pore noise reaching past the region's edge, which reproduced the defect where the plan's "two pits 0.6 cell apart" did not):
  1. *Holes from the octree walk* (46 open edges with deep pores). `Nets::mesh` skipped a box when the field at its middle was further than the box's size, which assumes a distance field. Sculpt offsets break that. The walk now adds twice the largest offset the detail grid can give in that coarse cell (`DetailGrid::max_abs_in`, `Field::detail_bound`; a trilinear value never passes its grid points'). Holes 46 → 0, the same triangles as with no pruning at all, and no measurable time change (`adaptive nets` 0.11 s on the region fixture before and after).
  2. *Pinches merged by the weld* (the plan's cause, 3 pinched edges on the pinch fixture). The new `adaptive::separate_pinches` runs `make_manifold` on the welded print mesh and moves each copy by max(0.005 mm, 0.02 × the mean edge length there) along its fan's normal, toward its fan's middle, with the other sheets as tie-break (D7). **Algorithm: tube field.** For a circle profile, the tube is the union of round cones over consecutive densified samples: `f(p) = min_i round_cone(p, a_i, b_i, r_i, r_{i+1})`, using the exact `round_cone` already in clay.rs:707. A minimum of exact distance fields is exact outside the union and a bound inside it, and it is 1-Lipschitz everywhere, so surface nets see a clean field. Caps are the end spheres. Twist does not apply to circles.

For a polygon profile, each span gets a rotation-minimising frame (the double-reflection method of Wang et al. 2008) computed once along the samples, and is evaluated as a rigid prism: `polygon_sdf(local.xy / s, p) · s` intersected with its two mitre half-spaces (the bisector planes between neighbouring spans). The union over spans is again a minimum of 1-Lipschitz functions. Taper and twist are linear within a span, which is exact enough for spans much shorter than the radius of curvature.

**Algorithm: segment tree.** `SegTree` is a BVH over span bounding boxes (each expanded by its radius), built once per `Geometry`. `sdf_within(p, bound)` walks nearest-first and stops when a node's box distance exceeds `min(best, bound)`. This turns the O(N) scan into about O(log N) per query and makes carves cheap far from their path. A tree of 4,096 spans costs about 200 KB.

**Algorithm: ClayPolish.** It works on the composed field T sampled on the detail lattice in the region, plus a 3-cell apron, and writes offsets to the written layer.
1. **Crease guard.** At each lattice point near the surface (|T| < 2 cells), take the normal `n = ∇T/|∇T|` by central differences, and the largest angle between `n` and the normals at its 6 neighbours. A guard weight `g = smoothstep(angle, 0.6 · angle, θ_max)` is 0 on creases and edges sharper than `angle` and 1 on smooth surface.
2. **Anisotropy guard** (keeps intended lines such as lip and lid lines that are rounder than `angle`): the shape operator from the Hessian of T projected on the tangent plane, eigenvalues κ1, κ2 (closed-form 2×2). Anisotropy `a = (|κ1| − |κ2|)/(|κ1| + |κ2| + ε)`. Lines and ridges have a near 1 and lumps a near 0. The final weight is `w = g · (1 − smoothstep(0.5, 0.8, a) · step(|κ1| · cell, 0.15))`: strongly anisotropic, strongly curved points are kept.
3. **Flow.** Explicit mean-curvature flow on T, as in `to_clay::smooth`: `T ← T + dt · w · falloff · |∇T| · div(∇T/|∇T|)`, with dt = 1/6 (stable) for `passes` passes, Jacobi, in fixed order. The default pass count for `amount` is `round(amount · 16)`.
4. **Volume.** With `keep_volume`, after each pass a uniform shift `c = −Σ ΔT / (N_surface)` is applied inside the region's surface band, so the enclosed volume changes by at most a cell × area × 1e-3. The sum is done by a fixed-order reduction over bricks (sorted keys), not a parallel float reduction, so it is deterministic.

A lump is a short, isotropic bump. Its mean curvature is large, its anisotropy low and its normals vary less than `angle` across a cell, so it flows away. A lid line is a long anisotropic groove (a ≈ 1) and is kept. A hard edge has normals that differ by more than `angle` across a cell and is kept.

**Algorithm: lumpiness.**
1. Sample N surface points evenly (Poisson-disc on the regular mesh, seeded, with a fixed order) and project each onto the field with `adaptive::along`.
2. At each sample p with normal n, evaluate the field on a small stencil in the tangent plane at two scales: the fine height `h_f(p)`, the field's zero along n (exact), and the smooth height `h_s(p)`, a Gaussian-weighted least-squares quadric fitted to field zeros at 24 tangent-plane offsets within σ = 4 cells. The residual is `r = h_f − h_s`, measured in cells.
3. Intended detail is excluded. A sample counts as intended when (a) it lies in a dab footprint of a ledger record whose brush makes texture (noise, alpha stamps, vdm, standard with an alpha, crease, pinch), or (b) the anisotropy at scale σ is ≥ 0.6 with |κ1|·σ ≥ 0.15 (a line or ridge), or (c) the crease guard of Stage 1c flags it as an edge.
4. Lumpiness is the RMS of r over non-intended samples, in cells. Per region, the same RMS over the region's samples. `worst` are the samples with the largest |r|, clustered 4σ apart.

Because the measure uses the field and cell units, it does not depend on the camera or the mesh resolution. The clay's `cell_size()` is the unit. For a clay with a `detail_cell`, the finest cell at p (`DetailGrid::cell_at`) is the unit.

**Algorithm: contour distance.** For each view, extract the boundary pixels of both masks. Compute the distance transform of each boundary (two-pass exact Euclidean, Felzenszwalb-Huttenlocher, in-house). `contour_mean` is the symmetric mean of boundary-to-boundary distance, converted to world units with `1/s` and to % of the subject height. IoU hides a thin missing ear; the contour distance does not.

**Algorithm: feature lines.** In a close-up crop:
- **Reference lines:** a Gaussian at 1 px, Sobel magnitude, non-maximum suppression and hysteresis (Canny), all in-house on the luminance, inside the subject mask.
- **Model lines:** the same Canny run on a render of `shade: curvature` plus depth discontinuities (depth gradient > 3 px-equivalent) and normal discontinuities (> 30°). A stylised drawing's lines for lids, mouth and brows correspond to creases, curvature extremes and occluding contours.
- **Measure:** `feature_chamfer` is the mean distance from each reference line pixel to the nearest model line pixel, and back, from the two distance transforms. `feature_recall` is the share of reference line pixels within 2 px of a model line.

**Tests**
- `lumpiness_ranks_noise`: a sphere with seeded noise amplitudes 0, 0.05, 0.1, 0.2 and 0.4 cell. The scores are monotone (Spearman 1.0), the clean sphere scores ≤ 0.01, and 0.4-cell noise scores ≥ 0.25.
- `lumpiness_ignores_intended_detail`: the same sphere with alpha-stamped pores (a texture brush record) and a crease groove, and no noise. The score is ≤ 0.015, and the pores' samples are flagged as intended.
- `lumpiness_is_resolution_independent`: one clay meshed at res 96, 128 and 192 scores within 10% (the field is the same; sampling differs).
- `contour_distance_catches_thin_parts`: a reference with a thin antenna missing from the model. IoU changes by < 0.01, but `contour_p95` rises by ≥ the antenna's length × 0.5.
- `multiview_compare`: three synthetic slots (front, right, back silhouettes of an ellipsoid with a nose) against the matching clay give IoU ≥ 0.97 in every view, and a model missing the nose has its worst view = right.
- `closeup_features_match`: a reference drawn as a disc face with two eye rings and a mouth arc, against clays with matching and shifted grooves. The matching clay gets `feature_pct` ≤ 1.0, and a mouth shifted 4% of the radius gets ≥ 3.0.
- `quality_report_is_deterministic`: the same reply (bit for bit) on 1 and 12 threads, and twice in a row.
- `quality_report_bounds`: 200,001 samples and 17 regions are refused before sampling.
- Stage 1b exit re-check: the thin tube's lumpiness is ≤ 1.5× the capsule chain's.

**Performance.** `quality_report` with 40k samples, 3 views and 2 close-ups takes ≤ 6 s on a 2M-triangle clay (field metrics ≤ 3 s, renders ≤ 3 s). A lumpiness render costs the field metric plus one render.

**Risks.**
- Thresholds calibrated on synthetic fixtures may be too strict or too loose on real sculpts. D14 thresholds are overridable per call, and the benchmark (§5) records the real distribution.
- Canny lines from a drawn reference include hatching and colour edges that the model will never have. `feature_recall` is reported next to chamfer, and the reference mask is eroded by 2 px to skip the outline, which the silhouette measures already cover.
- `intended_mask` from ledger footprints misses detail made by blobs (a sweep groove). The anisotropy rule catches lines; isotropic intended blob detail (a dimple made by a carve sphere) is counted as lumps. Regions can be excluded with `regions: [{..., "exclude": true}]`.

**Exit criterion.** All tests above pass. On the figurine fixture's synthetic copy (blob skeleton plus the seven defect geometries), `quality_report` names every injected defect in `failures` or `worst`, with no false failure on the clean parts.

- **Lumpiness** as specified (24 surface heights on three rings within σ = 4 cells, a Gaussian-weighted quadric, residual in cells, the unit `DetailGrid::cell_at`), with three deviations:
  1. *The fit's scale shrinks where it bends hard:* where the σ fit's larger curvature × σ passes 0.5, σ becomes 0.5/κ (at least 1.5 cells), so a small ball or a thin part is not read as a lump.
  2. *Rule (b) changes the fit, not the count.* The plan's line rule (anisotropy ≥ 0.6 with |κ1|σ ≥ 0.15) left lines out; at σ = 4 cells that is every limb under 27 cells across, and every thin tube, so a lumpy tube would never be seen. ### Stage 3a: polygon object and Catmull-Clark levels (L, 2.5 weeks)

**Status: done (2026-10-26)**, on branch `sculpt`, in two sub-stages (3a-1 the module, 3a-2 the object and tool); 74 tools. See the result paragraph at the end of this stage.

**Goal.** A first-class quad polygon object with subdivision levels, semi-sharp creases and limit evaluation. Stages 3b-4b build on it.

**MCP changes.** New tool `poly`:
```json
{
  "target": "object",
  "action": "info | from_clay | subdivide | set_level | crease | uv | project | rebuild | to_clay",
  "source": "clay object",        // from_clay, project
  "levels": 0..6,                 // subdivide: total levels to keep (refused above the face bound)
  "level": 0..6,                  // set_level: shown and rendered level
  "edges": [[i, j], ...],         // crease: vertex index pairs at level 0, at most 65536
  "sharpness": 0..10,             // crease: semi-sharp (0 removes, 10 = infinitely sharp)
  "angle": 0..180,                // crease: instead of edges, every edge whose dihedral exceeds this
  "name": "new object name"       // from_clay
}
```
`info` replies with faces, quads_pct, valence histogram, irregular_pct, boundary loops, non-manifold edges, genus, level face counts, crease count, UV state and `made_by`. `from_clay` makes a Poly from the clay's rest surface-nets quads, welded and made manifold: the quick, dense, unclean starting point (retopo in 3b is the clean one).

**Files and functions**
- New `src/poly/mod.rs` with `Poly { cage: Chunked<Vec3>, faces: Chunked<u32>, face_start: Chunked<u32>, creases: Arc<BTreeMap<(u32, u32), f32>>, levels: Vec<Level>, level: u8, uv: Option<Uv>, made_by: Option<Value> }`. `Chunked<T>` is the sculpt plan's 9a type: `Arc<Vec<Arc<[T; 4096]>>>` with `PartialEq = Arc::ptr_eq` per chunk, so the per-frame Scene clone and compare stays under the 50 µs guard.
- `src/poly/topology.rs`: CSR vertex-face and edge adjacency, built on demand and cached in `MeshLib`. Half-edges are not stored.

**Algorithm** (Jakob et al. 2015, "Instant Field-Aligned Meshes", made deterministic):
1. **Hierarchy.** Build a multigrid hierarchy on the input vertices by repeated matching (pair each vertex with its best unmatched neighbour by normal and distance, in index order), down to about 1,000 vertices.
2. **Curvature initialisation.** At each vertex, the principal direction κ1's eigenvector from the SDF Hessian of the clay field (exact on the field, not noisy mesh curvature; closed-form 3×3 eigen-solver). Confidence is |κ1 − κ2|·cell. Vertices with low confidence start from the propagated neighbour value.
3. **Orientation field (4-RoSy).** On each level from coarse to fine, smooth the field by repeated local averaging: for each vertex, rotate each neighbour's direction to the integer multiple of 90° that best matches, about the shared normal, and average. Constraints are fixed directions:
   - crease edges (dihedral > `keep_creases`): their direction;
   - guide polylines: the tangent of the nearest guide segment within 3 edge lengths;
   - polygroup borders: the border tangent;
   - the symmetry plane: its normal is a field direction at plane vertices.

   **Determinism:** vertices are coloured greedily in index order so no two neighbours share a colour, and colours are processed in a fixed order, each colour in parallel (multicolour Gauss-Seidel). The result is identical on any thread count.
4. **Position field.** The same hierarchy and colouring, solving for a lattice offset per vertex so that integer lattice points of spacing h are consistent across neighbours (the Instant Meshes position-field step). h comes from the target face count: h = sqrt(area / faces), scaled by the `adaptive` term `(1 + adaptive · |κ1|·h)^(-1/2)` and the density multipliers.
5. **Symmetry.** With `symmetry: x`, solve on the x ≥ 0 half, with the plane vertices' position field snapped to x = 0, then mirror. The two halves meet on a row of edges on the plane.
6. **Extraction.** Collapse input vertices that map to the same lattice point (union-find in index order), keep edges between collapsed groups whose lattice offsets differ by one step on one axis, and form faces from the resulting graph's minimal cycles (length 3-6).
7. **Cleanup.**
   - Remove valence-2 vertices.
   - Fix pentagons and triangles by local splits: a triangle next to a pentagon merges into two quads where possible.
   - With `pure_quads`, one Catmull-Clark-style split makes every face a quad. The target edge length is doubled before extraction so the split lands on the requested count.
8. **Fit.** Project vertices to the clay surface (`adaptive::along` with the field), then 3 rounds of tangential Laplacian relaxation (each vertex moves to its neighbours' centroid in its tangent plane), projecting again after each round. Crease vertices relax only along their crease.

- **Pipeline.** The clay's rest mesh (or fine mesh) is welded as `from_clay` welds it, decimated with meshopt to about 2 × (8 points per output face) triangles, then remeshed isotropically in three rounds (split long edges red-green, collapse short ones under the link, length and fold checks, flip toward valence 6, relax tangentially onto the field). The hierarchy pairs points in index order (normals within 90 degrees, by normal agreement per area) down to about 1,000 points; the 4-RoSy field (extrinsic quarter-turn matching, Jakob et al.) and the position field (lattice points, `middle_point` compares, rounding to the vertex) are solved coarse to fine, 8 sweeps a level. Quads come from the lattice: points on one lattice point collapse (union-find in index order), points one step apart on one axis link. **Deviation:** faces are traced as a rotation system (each point's edges sorted by angle about its normal, each face the walk turning clockwise), so every directed edge is in exactly one face and the result is always a closed, consistently wound surface; walks passing a point twice lose an edge and are traced again (the plan's "minimal cycles 3-6" can leave holes). Faces of 7 or more sides get a middle point and a quad fan, hexagons split on their best diagonal. Odd faces are paired across straight or turning strips of up to 8 quads (the strip re-split by a ladder of diagonals), first only where that leaves no more irregular points, then one more; ladders that fold a quad or lay three of its points along a feature line are refused. With `pure_quads` the cage is split once (Catmull-Clark topology without smoothing, the lattice step doubled before extraction so the count lands), then fitted: points onto the field along their normals, three rounds of tangential relaxation, each followed by projection; feature points slide along their line, corners stay, a move that would leave a point farther off the surface is not taken.
- **Edge flow.** Curvature is the clay field's Hessian (central differences at 2 cells, closed-form 2×2 shape operator) and pulls the field toward the larger principal direction with a weight from |κ1 − κ2|·h (**deviation:** a soft pull at every level, not only the start, which the coarse-to-fine solve would overwrite). Creases, guides (laid onto the surface every input edge), polygroup borders (through the middles of edges whose ends differ, smoothed) and the symmetry plane are lines: a point near one is held to its direction and its lattice is snapped (by less than half a step) so a lattice line runs through the line's nearest point; corners hold both lines. Where two lines cross (a guide or border over the plane, a guide over a crease) the crossing is a fixed corner. After extraction, output points within 0.35 of a step of a line are put on it. The plane's band is 0.6 of a step (its cut needs the loop exactly on x = 0); a guide's or border's is at most that, a fifth of its extent and at least 1.5 input edges; if the cleaned cage has more pieces than the surface (a tight loop on a concave part tore the lattice), guides and borders are solved again with the narrow band and a note says so.
- **Spacing.** h = sqrt(area / faces) (a quarter of the faces with the split), scaled per point by `(1 + adaptive·|κ1|·h)^(-1/2)` and the density regions (a smooth fade to 1), smoothed, renormalised to the face count; neighbours compare lattices at their mean spacing (the variable-scale approximation). `density_regions_shorten_edges`: a scale-0.5 region gives edges 0.0278 near its middle against 0.0402 elsewhere.
- **Symmetry. Deviation:** not solved on a half: the whole surface is solved with the plane as a held line, the cleaned cage is cut at its loop on the plane (points within 0.3 of a step of it go onto it; a face across it or in it refuses the cut, and the cage is made whole with a note), the half is split and fitted with its border sliding in the plane, every border point is put on x = 0, and the half is mirrored and joined there. `symmetry: auto` (the default) mirrors when the clay's field at the mirror image of its points is within a cell of zero and the polygroups are mirrored too. Symmetry error is 0 by construction.
- **Determinism.** Every per-point step is a pure function in its own slot (`par_chunks`), colours of the multicolour sweeps run in order, matching, union-find, pairing and tracing are sequential in index order, and no hash-map order reaches the output. `retopo_is_deterministic`: the head and the box (with a guide and symmetry) give the same Poly hash on 1 and 12 threads.

### Stage 3c: projecting clay detail onto subdivision levels (L, 2 weeks)

**Status: done (2026-10-26)**, on branch `sculpt`, in three sub-stages (3c-1 `poly project`, 3c-2 `poly uv`, 3c-3 `bake lowpoly {poly, level}` and maps) and a review pass; 75 tools. See the result paragraph at the end of this stage.

**Goal.** The sculpted clay's detail is carried onto the quad mesh as per-level displacement, then baked into displacement and vector-displacement maps that reproduce the clay when reapplied.

**MCP changes.** `poly action: project`:
```json
{ "target": "poly", "action": "project", "source": "clay object",
  "levels": 1..6,                    // project onto this many levels (subdividing as needed)
  "mode": "vector | scalar",         // vector (default) captures sideways detail and overhangs up to a cone
  "cone": 0..80,                     // degrees from the limit normal a vector search may lean (default 45)
  "reach": r }                       // farthest search distance (default 3 x the level-0 edge length)
```
`poly action: uv` (needed for maps): `{ method: "xatlas", texel_density?, padding_px?, udim: false }`. `bake` gains `lowpoly: {poly: target, level}` with maps `displacement` and `vector_displacement` from the Poly.

**Files and functions**
- `src/poly/project.rs`:
  - `project(poly, field, levels, mode, cone, reach) -> Vec<LevelDisplacement>`. For each level from coarse to fine, the displacement is the residual after the coarser levels, so each level holds only its own band of detail.
  - Scalar: the nearest surface crossing along the limit normal (`adaptive::along`).
  - Vector: the nearest point on the clay's zero set within the cone, found by projecting with field Newton steps (`p − ∇T·T`) from the scalar hit and accepted only if the angle to the normal is ≤ cone. This captures sideways detail that a normal-only search cannot, which is the parity doc's known limit of the 8b vector maps (R and G about 0).
- `src/poly/uv.rs`: xatlas (present) on the triangulated cage, with chart boundaries snapped to quad edges (a quad's two triangles are always in one chart). Subdivided UVs are face-varying linear (boundary corners kept).
- `bake.rs:391` `displacement`: a `Source` for a Poly level mesh, reusing the raster, sampling and fill code unchanged. The vector map uses the level frames F_k, not the interpolated triangle normal.
- `film/dice.rs:211` `apply_baked` stays the verifier: maps reapplied to the level-L mesh are compared with the clay.

**Tests**
- `project_vector_captures_overhang`: a clay with a mushroom overhang on a plane. Vector projection reproduces the overhang (Hausdorff ≤ 1 cell); scalar does not (asserted, documenting the difference).
- `project_round_trip`: retopo (5k) of a sculpted head fixture, projected over 4 levels. Level-4 surface to clay Hausdorff ≤ 0.5 cell, and normal RMS error ≤ 4°.
- `maps_reapply`: vector EXR and scalar PNG maps, baked from level 0 and reapplied through `apply_baked` at level 4. Hausdorff to the clay ≤ 0.75 cell (vector) and ≤ 1 cell (scalar, on a height-field fixture).
- `project_bands`: the per-level RMS displacement falls with level on a noise-free fixture (each level carries only its band).
- `project_is_deterministic` and `project_settles`: the clay's unchecked ledger is settled before reading (the reply's `settled` count).

**Performance.** Projection of a 5k cage over 4 levels (1.3M points) in ≤ 8 s, and a 4K vector map in ≤ 6 s.

**Risks.**
- Vector search can latch onto a neighbouring surface across a thin gap, such as between lips. The cone, the reach bound and walking along the normal first (`adaptive::along` never jumps across a gap) limit this. Where scalar and vector disagree by more than reach/2, scalar wins and the reply counts it.
- UV seams on displaced levels can crack if seam vertices read different texels. Vector displacement is applied per vertex (not per face corner), with seam vertices reading the average of their charts' samples.

**Exit criterion.** `project_round_trip` and `maps_reapply` pass. The benchmark retopo (3b exit) projected to level 4 is within 0.5 cell of its clay.

### Stage 4c: groom brushes (M, 1.5 weeks)

**Status: done (2026-10-26)**, on branch `sculpt`, in one commit after the Stage 4b review fixes; 77 tools. See the result paragraph at the end of this stage.

**Goal.** Agents shape hair guides directly: comb, lengthen, clump, twist, cut, smooth and puff, with falloff and symmetry, colliding with the head.

**MCP changes.** New tool `groom`:
```json
{
  "target": "hair object",
  "strokes": [{                              // at most 64 per call
    "brush": "comb | lengthen | shorten | cut | clump | twist | smooth | puff | relax",
    "points": [[x,y,z], ...],                // world, 1..256: the brush path (or one point)
    "radius": r, "strength": 0..1,
    "falloff": "smooth | linear | sharp | flat",   // as sculpt presets
    "direction": [x,y,z],                    // comb: the way to comb (default: the path's direction)
    "length": l,                             // lengthen/shorten: by this much; cut: keep at most this long
    "plane": { "point": [x,y,z], "normal": [x,y,z] },  // cut: trim beyond the plane instead
    "angle": degrees,                        // twist
    "affect": "tips | roots | all",          // where along each guide the brush acts (default tips-weighted)
    "mirror": true,                          // X symmetry (default: the hair's mirror flag)
    "collide": "head clay object"            // keep guides outside this clay (default: the hair's parent clay)
  }]
}
```
Reply: guides changed, mean and max point moves, length change, collisions resolved, and a front and right render of the guides.

**Files and functions**
- New `src/groom.rs`: `apply(hair: &mut Hair, strokes: &[GroomStroke], collide: Option<&Field>) -> GroomReport`. The brush maths uses `brush::curve` falloffs and `brush::symmetry`.
- `hair.rs`: a guide point count bound (512 per guide, 4,096 guides) and the re-sanitize after a groom.
- `app/` handler and dispatch. UI: a Groom tool mode in the HUD that records a drag and sends `groom` on release (sculpt Stage 1c pattern).

**Algorithm.** Each guide point gets a weight from the falloff of its distance to the brush path, times an `affect` ramp along the guide (tips 0→1 from root to tip, roots 1→0). Roots never move.
- **comb**: rotate each segment toward `direction` by `weight · strength`, keeping segment lengths with follow-the-leader from the root.
- **lengthen / shorten**: extend along the tip tangent, or trim from the tip.
- **cut**: trim to `length`, or at the plane intersection.
- **clump**: pull points toward the weighted centroid of guides in the brush at the same arc-length fraction.
- **twist**: rotate points about the local clump axis by `angle · weight`.
- **smooth**: Laplacian along each guide.
- **puff**: lift root-side segments along the scalp normal.
- **relax**: even out spacing between neighbouring guides.

After each brush, collision pushes every point outside the clay field by at least the hair's `lift`, with a few projection steps along ∇T, then lengths are restored by follow-the-leader. The order is fixed (guide index, then point index), so the result is deterministic.

**Tests**
- `comb_aligns`: 40 guides combed toward −Y. The mean angle of tip segments to −Y falls from 60° to ≤ 10°, and every guide keeps its length within 1%.
- `cut_plane`: no guide point lies beyond the plane, and roots are untouched.
- `collide`: after a comb into the head, no point lies inside the clay (field ≥ lift).
- `mirror`: an X-mirrored stroke gives mirrored guides within 1e-5.
- `groom_bounds`: 65 strokes or 257 points are refused.
- `ui_groom_matches_mcp`.

**Performance.** One stroke over 4,000 guides of 32 points takes ≤ 20 ms.

**Risks.** Without a ledger (D20), a groom cannot be selectively undone; whole-scene undo works. If agents need replay, a `groom_log` like the rig's `WeightStroke` log (rig.rs) is the follow-up.

**Exit criterion.** The tests pass, and the benchmark's hair (a tuft and short side locks) is groomed only with `groom` from grown guides, with its film render showing no strands through the head (`hair::inside_count` = 0).

- **Brushes.** Each point's weight is the falloff (sculpt's presets and curves) of its distance to the path times the `affect` ramp times the strength; roots never move. comb turns each segment's direction toward `direction` (or the path's own direction at its nearest segment) by its end point's weight and rebuilds from the root with the old lengths; lengthen continues along the tip at the guide's own spacing (at most 512 points a guide, then the last segment stretches, counted); shorten trims from the tip (keeping 1% at least); cut keeps at most `length` or trims at a plane (a guide whose root is past it is left alone and counted); clump pulls points toward the weighted centre line of the guides in the brush (tabulated at 33 fractions of length); twist turns them about that line; smooth is a Jacobi Laplacian along each guide; puff turns segments toward the scalp normal at the root (roots ramp); relax moves points so their distances to the 6 nearest reached guides (at the same fraction) approach their roots' spacing. Each strand is a pure function of its index. *Viewport:* one card a guide lying on the surface (its face along the root's normal, 1.6 spacings wide), the white strand texture times the clay's colour as the vertex colour, kept out of the clay like other cards, built on the card thread. *Bounds* are checked from the arguments before anything is allocated (counts, lists at most 64, lengths, lie, jitter, colours, segments 2-16, the density against the area). *UI:* Create > Fur on Selected Clay and Create > Eyelids on Selected Clay send the requests an agent sends (`stage7_tests::ui_lids_and_fur_match_mcp`). *Measured on Pip* (lids replaced, the face 5 mm, the rest 13.3 mm; nose, mouth, lids, sockets and brows excluded; `app/fur_tests.rs`): grow 360-430 ms (12,000 candidates, 731 excluded, 2,000 guides, surface 1.76 m², furred 1.65 m²); guide roots' nearest spacing 23.4 mm with CV **0.112** (random roots 0.56; `elimination_spreads_evenly`: 1,000 of 6,000 on a square, CV 0.108); **157,275 film strands** of 160,000 in 646 ms (2,725 left out on excluded parts), strand roots' CV **0.181** (random in each cell gave 0.53, which the spiral replaced); 0 strands inside the clay, 0 roots on excluded blobs, 0 rooted by an eye, 0 into an eye (every 7th strand checked, 22,468); root colour the clay's within 0.01 for all but 11 (kept-out strands at the nose's 6 mm colour edge, at most 0.038); 21,792 blue and 700 pale strands sampled; guides 4.9 mm on the face, 13.3 mm on the body; strands the same bits on 1 and 12 threads; save, new and open keep the hair and its strands; the same grow gives the same guides; a fur settings edit and the grow undo in one step each; 8 refusals change nothing. ## 7. Risks

1. **Retopo quality is the largest risk** (3b). Field-aligned methods are robust but not artist-grade on complex parts. Guides, density regions and the irregular-vertex bound give agents control. The benchmark's retopo bound is set where Instant-Meshes-class methods succeed on smooth organic shapes.
2. **Two colour sources** after Stage 4b (clay paint and Poly tiles). The guide rule and `bake udim` transfer keep one direction of flow.
3. **Metrics that do not match taste.** Lumpiness and contour error measure cleanliness and fidelity, not appeal. The final sign-off stays human by design.
4. **Saved-file compatibility.** D5 keeps legacy sweeps bit-identical. Every new field is serde-default and skipped when default, so old scenes load and mesh as before (pinned hashes in each stage).
5. **Determinism of new solvers.** Multicolour Gauss-Seidel and Jacobi kernels are deterministic on one machine. Cross-platform bit-equality is not promised (the sculpt plan's Risk 3 applies).
6. **Tool-surface growth** (72 → 79). `poly` folds nine actions. If agent evals show tool-selection errors, `guides` folds into `quality_report` and `create_character` into `create_object`.
7. **Reference sheets of unknown style.** Line art, painted art and photos give different feature-line maps. `feature_recall` and the user's sign-off cover this.
8. **Polygon object scope creep.** Poly is a second geometry path through export, film and paint. The plan keeps it derived (D1) and without modelling ops (no `poly_edit`), and every Poly feature has its own exit test.
9. **GPU limits for heavy dicing.** The CPU fallback and the dicing budget refusal apply.
10. **ClayPolish on large regions.** Bounded band sizes and refusals with a smaller suggested region.

- `quality_report` is the agent's main loop tool. Its `worst` points must be in the same world space that `sculpt` and `edit_clay polish region` accept, so an agent can act on a failure in one call. (They are world space, and `region` is object space. **Correction:** `polish.region` accepts `space: world|object`, default world for consistency with `sculpt`.)

### Underweighted risks
- **Legacy sweep users.** D5 keeps old scenes bit-identical but leaves them with the old fuzzy field. **Addition:** `edit_clay update` with `{field: "segments"}` on an existing sweep upgrades it, and `quality_report` adds a hint when it finds legacy sweeps among its worst points.
- **Carve culling exactness relies on the clamp.** A test pins mesh hashes with and without the cull on fixtures with round, sharp and chamfer carves. If any differs, the cull is restricted to sharp and round carves.
- **Early-returning edit_clay** changes timing for agents that read bounds from its reply. Bounds are omitted, not stale, when `mesh_pending`, and the agent guide text says to call `get_scene` or wait on `job_status`.
- **Feature-line compare on stylised references** may reward any curvature near the expected lines. `feature_recall` alone can be gamed by many creases. **Correction:** report precision too (the share of model lines within 2 px of a reference line), and the benchmark requires precision ≥ 0.6 alongside recall ≥ 0.8.
